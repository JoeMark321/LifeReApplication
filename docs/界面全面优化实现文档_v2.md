## 1. 界面内容优化：让初学者"看图学生命周期"

### 1.1 问题

旧首页只是一张纯文字列表，初学者看到 6 行标题不知道从哪开始、回调顺序是什么、点击后会发生什么。

### 1.2 方案

| 改动 | 实现 | 文件 |
|---|---|---|
| 生命周期流程图 | 自定义 View 绘制 7 个回调 chip + 箭头，当前阶段蓝色高亮、已走过绿色、未到达灰色 | [LifecycleFlowView.java](../app/src/main/java/com/example/lifereapplication/ui/widget/LifecycleFlowView.java) |
| 一句话引导 | 列表第 0 项是引导卡：怎么读、点哪里、右上角 ⋮ 干什么 | [item_home_header.xml](../app/src/main/res/layout/item_home_header.xml) |
| 序号徽标 | 难题卡片显示 1、2、3… 圆形徽标，与详情页"正在加载序号 N"呼应 | [item_problem.xml](../app/src/main/res/layout/item_problem.xml) |
| 快捷入口 | 新手必读 / 踩坑清单 / 面试速记 三张卡，直达指定难题 | `MainActivity.onQuickActionClick()` |
| 阶段实时解说 | Activity 每次回调都会更新流程图高亮 + 一句"该阶段该做什么" | [ProblemAdapter.updateLifecycleStage()](../app/src/main/java/com/example/lifereapplication/ui/main/ProblemAdapter.java) |

### 1.3 为什么用自定义 View 画流程图

静态图片不能跟随深色模式，也不能响应"当前处于哪个回调"；一堆 TextView 又画不出箭头。自定义 View 只在 `setCurrentStage()` 变化时 `invalidate()`，重绘成本可忽略，且天然适配任意屏宽。

## 2. 数据管理策略：分级存储

### 2.1 数据类型梳理

| 数据 | 存储位置 | 理由 |
|---|---|---|
| 学习主题内容（标题/描述/方案/分类/序号/重点标记） | **Room 数据库**（`lifere.db`） | 需要跨进程启动保留；支持按分类/序号结构化查询 |
| 单个主题详情 | **LruCache（4MB）+ DB 兜底** | 详情被反复打开，命中内存省一次 IO |
| 分类列表 | 内存缓存 | 内容少、几乎不变，重复查库收益低 |
| 生命周期回调日志 | **仅内存**（40 条有界双端队列） | 高频写入，落库会造成无效 IO 与表膨胀；进程死掉后旧日志无阅读价值 |
| 提示偏好/权限开关 | **SharedPreferences** | 少量键值型数据，引入数据库属于过度设计 |
| 当前筛选分类 | 仅内存（ViewModel 字段） | 典型易失 UI 状态 |

### 2.2 性能设计

- **单例数据库**（[AppDatabase.java](../app/src/main/java/com/example/lifereapplication/data/local/AppDatabase.java)）：全局一个连接；未开 `allowMainThreadQueries()`，误在主线程查询会直接抛异常，把问题暴露在开发期。
- **读多写少**：写操作只在首次建库 seed 时发生一次；之后全部走内存缓存。
- **详情异步读取**（[ProblemRepository.getProblemByIdAsync()](../app/src/main/java/com/example/lifereapplication/data/repository/ProblemRepository.java)）：`DetailViewModel` 必须走异步入口，否则 Room 在主线程查询直接崩溃。
- **懒加载**：RecyclerView 本身即懒加载——仅可见项会被创建/绑定；首页列表是唯一滚动容器，避免了 ScrollView 嵌套导致的"一次性测量全部 Item"。

## 3. Toast 提示系统：三套实现 + 统一出口

### 3.1 三种实现对比

| 方案 | 类 | 特点 | 适用 |
|---|---|---|---|
| 原生 | [NativeToast](../app/src/main/java/com/example/lifereapplication/util/toast/NativeToast.java) | `Toast.makeText`，零成本、线程安全 | 临时调试、最低成本反馈 |
| 自定义（重写样式） | [CustomToast](../app/src/main/java/com/example/lifereapplication/util/toast/CustomToast.java) | `setView()` 替换布局：图标 + 圆角半透明背景 + 自定义位置；5 种语义类型（成功/错误/警告/信息/默认） | 品牌一致的中量反馈 |
| 现代化 | [ModernToast](../app/src/main/java/com/example/lifereapplication/util/toast/ModernToast.java) | Material Snackbar：可带操作按钮、可上滑关闭、自动适配深色/无障碍 | 需要撤销/查看等补救动作的场景 |

> 关于"@ovia 框架重写 Toast"：未引入第三方框架。原生 `Toast.setView()` 已能完全自定义布局，不增加依赖、不需要 Application 注册，可控性更好。`ToastLabActivity` 内三种实现可直接对比验证。

### 3.2 统一出口与提示权限管理

[ToastCenter](../app/src/main/java/com/example/lifereapplication/util/toast/ToastCenter.java) 是全项目唯一提示出口：

```java
// 业务代码只调用这个
ToastCenter.show(activity, message, CustomToast.Type.SUCCESS);
```

- **样式路由**：按用户在设置页选的偏好（NATIVE/CUSTOM/MODERN）分发；
- **权限管理**：某类提示被用户关闭 → 直接 return，完全静默；当前样式被关时按 `现代化→自定义→原生` 自动降级，保证关键反馈不丢；
- **静默提示**：`ToastCenter.showSilent(tag, msg)` 只写 Logcat 不弹 UI，用于高频低价值反馈（生命周期追踪、加载态）。

### 3.3 组合提示矩阵

| 场景 | 方式 | 实现位置 |
|---|---|---|
| 轻量反馈、不打断 | Toast / Snackbar | 提示实验室 |
| 必须用户决策 | 模态对话框 | [DialogHelper](../app/src/main/java/com/example/lifereapplication/util/DialogHelper.java) |
| 应用在后台 | 系统通知 | [NotificationHelper](../app/src/main/java/com/example/lifereapplication/util/NotificationHelper.java) |
| 高频低价值 | 静默（Logcat） | `ToastCenter.showSilent()` |

## 4. 页面导航：右上角下拉菜单

### 4.1 结构

- 所有页面继承 [BaseMenuActivity](../app/src/main/java/com/example/lifereapplication/ui/nav/BaseMenuActivity.java)：统一 `Toolbar`（品牌蓝底白字，副标题固定显示 **MVVM 架构**），菜单项由代码动态填充（即右上角 ⋮ 三点下拉菜单）。
- 每页通过 `destinations()` 声明自己的菜单；点击后**先弹该页面独有的提示文案，再执行 Intent 跳转**；目标是当前页时只提示不跳转。

### 4.2 每页独有提示文案示例（首页）

| 菜单项 | 提示 |
|---|---|
| 返回本页 | 当前就在首页，无需重复跳转（警告样式） |
| 生命周期演示 | 从【首页】跳到【生命周期演示】—— 实时观察回调顺序 |
| 提示实验室 | 从【首页】跳到【提示实验室】—— 对比三种 Toast |
| 设置 | 从【首页】跳到【设置】—— 管理提示权限与样式 |
| 关于本项目 | LifeReApplication v2.0 · MVVM + Room + LiveData（成功样式） |

详情页/演示页/实验室/设置页各自维护一套"从【X】跳到【Y】"文案，见各 Activity 的 `destinations()`。

### 4.3 页面清单（均已注册 AndroidManifest）

| 页面 | 职责 |
|---|---|
| [MainActivity](../app/src/main/java/com/example/lifereapplication/ui/main/MainActivity.java) | 首页：引导卡 + 流程图 + 序号列表 |
| [DetailActivity](../app/src/main/java/com/example/lifereapplication/ui/detail/DetailActivity.java) | 详情：分类/难度 chip + 描述卡 + 方案卡 |
| [LifecycleDemoActivity](../app/src/main/java/com/example/lifereapplication/ui/lifecycle/LifecycleDemoActivity.java) | 三个实验（跳详情/对话框风格页/回桌面）+ 实时回调日志 |
| [DialogStyleActivity](../app/src/main/java/com/example/lifereapplication/ui/dialog/DialogStyleActivity.java) | 半透明主题页，验证"宿主只 onPause 不 onStop" |
| [ToastLabActivity](../app/src/main/java/com/example/lifereapplication/ui/toast/ToastLabActivity.java) | 三种 Toast + 静默/对话框/通知动手对比 |
| [SettingsActivity](../app/src/main/java/com/example/lifereapplication/ui/settings/SettingsActivity.java) | 提示样式偏好 + 权限开关（SharedPreferences） |

## 5. 使用说明（上手路径）

1. 启动应用 → 依次弹出三种 Toast 演示，流程图蓝色高亮 `onCreate`；
2. 点击列表序号卡片 → 详情页（提示"从【首页 · 序号N】跳到【详情页】"）；
3. 右上角 ⋮ → **生命周期演示** → 点"实验 2"打开对话框风格页 → 返回后日志显示宿主**没有 onStop**；
4. ⋮ → **提示实验室** → 逐个按钮体验三套提示 + 通知/对话框；
5. ⋮ → **设置** → 关掉"允许现代化 Snackbar"再回实验室点 Snackbar → 提示自动降级为自定义 Toast；
6. ⋮ → **设置** → 关掉"记录生命周期回调日志" → 演示页日志不再增长。

## 6. 测试方法与验收标准

### 6.1 功能验收

- [x] `./gradlew assembleDebug` 构建通过（BUILD SUCCESSFUL in 11s）
- [ ] 首页可滚动；流程图当前阶段蓝色；点击卡片有缩放反馈并跳详情
- [ ] 旋屏后列表与筛选状态保持（ViewModel 跨配置变更）
- [ ] 对话框实验：宿主仅 onPause，日志无 onStop
- [ ] 设置关闭某类提示后，该类提示完全静默；全关时自动降级
- [ ] 详情页传无效 ID 显示错误 Toast 并自动关闭
- [ ] 通知点击回到首页并自动消失

### 6.2 性能检查点

- 详情二次打开应无 DB 查询（LruCache 命中，可在 DAO 打日志验证）
- Profiler 观察滚动时无内存抖动（卡片绑定路径零对象分配以外的开销）
- 生命周期日志上限 40 条，`LifecycleEventLog.size()` 恒 ≤ 40
