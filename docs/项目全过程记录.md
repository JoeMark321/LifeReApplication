## 1. 项目定位

**生命周期Re** 是一个 Android 生命周期教学应用：把抽象的 Activity 生命周期变成可操作、可观察、可验证的实验。

- 首页按序号列出 9 个生命周期难题（从七回调顺序到进程回收），点进去看完整解答
- 每个页面都**亲身演示**自己正在经历的回调：右上角菜单跳转时看 A→B 时序、对话框风格页验证"只 onPause 不 onStop"、横向滑动区验证手势冲突裁决
- 开发语言 Java，架构 MVVM，minSdk 30 / targetSdk 37

```
│   ├── model/       Problem 领域模型
│   ├── prefs/       AppPreferences（SharedPreferences：偏好/进度/权限）
│   └── repository/  ProblemRepository（唯一数据入口，LruCache 4MB 分级缓存）
├── ui/
│   ├── chapter/     ViewPager2 章节联动
│   ├── detail/      难题详情（ScrollView 滚动记忆）
│   ├── dialog/      对话框风格 Activity（半透明教学）
│   ├── lifecycle/   生命周期演示（3 实验 + 实时日志）
│   ├── list/        ListFragment 状态保持 + 演示一/二
│   ├── main/        首页（流程图+横幅+序号列表）
│   ├── nav/         BaseMenuActivity / NavDestination（右上角菜单框架）
│   ├── settings/    提示权限与样式设置
│   ├── toast/       提示实验室
│   └── widget/      LifecycleFlowView 自绘流程图
└── util/
    ├── toast/       六件套（Throttle/Queue/Dispatcher/QueueHost/Center/三实现）
    ├── ScrollStateKeeper.java
    ├── DialogHelper / NotificationHelper
```

**数据分级存储**：

| 数据 | 存储 | 理由 |
|---|---|---|
| 教学内容（9 难题） | Room `lifere.db` | 跨启动保留 + 结构化查询 |
| 详情访问 | LruCache(4MB) + DB 兜底 | 反复打开省 IO |
| 生命周期日志 | 内存有界队列(40) | 高频写，落库=无效 IO |
| 提示偏好/章节进度/tab/上次页面 | SharedPreferences | 少量键值型 |
| 滚动状态 | 内存 LruCache(16条) + SP 双缓存 | 覆盖进程被杀 |

### 阶段 4：全面屏适配（b05d40f → 9a8b0d7）

### 阶段 6：开屏动画（cb436a0 → 9184330 → c658892 → 763d856）

## 5. 核心技术实现详解

### 5.1 Toast 系统（MVVM 六件套）

```
ToastDispatcher（节流裁决 → 入队）
 ├─ ToastThrottle：2s 窗口 / 3 次上限（纯逻辑，7 项单测）
 └─ ToastQueue：LiveData 队列头 + 串行计时（永不互相遮罩）
        │ observe（生命周期感知：页面 STOPPED 自动暂停渲染）
   ToastQueueHost → ToastCenter（样式路由 + 权限管理 + 全关自动降级）
        → NativeToast / CustomToast(setView+图标) / ModernToast(Snackbar)
```

业务侧一行：`ToastDispatcher.dispatch(activity, msg, type, long)`。

### 5.2 全面屏适配（跨版本自动）

| 层 | 内容 |
|---|---|
| 主题 | statusBarColor=品牌蓝（11~14 着色）+ shortEdges 刘海 + windowBackground=bg_page |
| 代码 | BaseMenuActivity 监听 android.R.id.content insets：Toolbar padding.top=状态栏+刘海；content padding.bottom=手势条 |
| Toolbar | 全部 `wrap_content + minHeight=actionBarSize`（挖孔屏 padding 撑高不挤压标题） |
| 主题复用 | values 定义 Theme.LifeRe.Core，values-night 只改父继承 |

### 5.3 ViewPager2 + FragmentStateAdapter

- `createFragment` 每次新实例 + arguments 传参（进程被杀不丢）
- TabLayoutMediator 双向联动；onPageSelected 持久化章节进度
- 恢复：setCurrentItem(last, false) 在 Mediator.attach 之前 → tab/页面一次到位无闪动
- 不可见页 onDestroyView 保留 FragmentState，滑回状态自动恢复

### 5.4 手势冲突（横幅嵌列表）

水平 RV 嵌垂直 RV，系统按初始位移方向自动裁决（dx>dy 横幅消费并锁定），零自定义拦截代码；固定 108dp 高度 → 复用率 100%。

## 7. 滚动状态保持方案的四次演进

> 这是本项目迭代最多的功能，四轮演进每轮都有明确的需求驱动与技术教训。

### v1（349c3d0）：基础双缓存
保存 `findFirstVisiblePosition + firstChild.top - paddingTop`；恢复用 `post{}` 延迟滚动。
**缺陷**：post 先画顶部再跳 → 抖动；减 paddingTop 造成恢复偏上。

### v2（296465f）：负偏移修复
发现条目半截滚出时 `child.top` 为负，被 clamp 归零 → "回到完整条目头"。
修复：负偏移合法，原样保留。**验证通过**（返回前后截图逐像素一致）——但校正逻辑当时是 `delta = target - child.top`，因 pending 已精确而 delta≈0，**掩盖了方向 bug**。

### v3（4142b92）：误解需求，矫枉过正
把演示一也改成"条目头对齐、偏移恒 0"。用户纠正：一要精确、二才对齐。

### v4（e904059 → e2c5a1c → 6348759）：最终形态
- **保存**（两模式共用）：`pos = findFirstVisibleItemPosition`，`offset = firstChild.getTop()` 原始像素（可为负）
- **恢复分流**：
  - `MODE_EXACT`（演示一/章节/首页）：pending `scrollToPositionWithOffset(pos, 0)` + PreDraw `scrollBy(child.top当前 − savedTop)` → **逐像素还原半截**
  - `MODE_ITEM_HEAD`（演示二）：pending 同上 + PreDraw `scrollBy(child.top当前 − paddingTop)` → **条目完整贴顶**
- **反漂移双保险**：
  1. pending anchor 统一 offset=0（该值定位结果在所有 ROM 下确定，负偏移塞 anchor 有解析不精确风险）
  2. PreDraw 用 `scrollBy`（纯像素滚动零误差），且**监听直到目标 child 布局完成才移除**
- **历史 bug 定性**：曾把"目标值"直接当 `scrollBy` 滚动量——方向相反，每轮重进反向偏移 2×偏移量，反复进出从 #58 漂到 #40 多

**最终验证**：滑到 #58 半截 → 退出 → 重进反复多轮，位置钉死在同一像素位。

## 9. Git 管理规范
